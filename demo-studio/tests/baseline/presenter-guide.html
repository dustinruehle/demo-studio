Live demo · run of show

Beats from cold start to composition. Default posture: mock models, local, no keys. You only Ctrl-C an agent worker for the durability beats.

Opening talk track

There are two layers of durability here. The outer harness is the business process. The inner harnesses are the agents themselves. In mock mode we stub only the model, never the integration, so everything you see is real except the words the model would have said.

What you are pointing at

PLATFORM lane

Server-side truth. Survives a worker dying. Point here to prove durability.

WORKER lane

Live worker state. Goes OFFLINE when that worker is down, which dims the pipeline.

Pipeline

The ordered steps of the run.

Activity feed

Each agent's model and tool calls as they land as Activities.

Beat 1

Happy path

baseline
Goal
One durable run completes with every call recorded.
Do
  1. Click Start happy.
Watch
  • Steps go green in order.
  • PLATFORM goes RUNNING → COMPLETED.
Why
No queue, no glue; every call is a recorded Activity.
Beat 2

Money moment

kill worker
⌨ Ctrl-C the worker, leave it stopped. Restart later with cmd worker-a.
Goal
Kill a worker mid-flight; the run survives and resumes.
Do
  1. Ctrl-C the worker.
  2. Start the run.
  3. Restart the worker.
Watch
  • WORKER flips OFFLINE and the pipeline dims; PLATFORM stays RUNNING.
  • After restart it resumes exactly where it was.
Why
We killed the worker and lost nothing. Earlier steps are not re-run.
Timing: take the worker down first, then start the run, so you are never racing the clock.

Switches

Local to Cloud
export ADDRESS=<ns>.tmprl.cloud:7233

Unset means local dev server and mock models. Restart the affected worker after changing env.

Troubleshooting

Worker won't start: run the preflight; it re-adds the integration extras and verifies imports.
Reset: Ctrl-C all terminals; local dev server state is in-memory.
